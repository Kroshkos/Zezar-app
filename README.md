# Zezar-app — мобильный клиент системы «ЦЕЗАРЬ»

React Native (Expo) приложение к сервису [Zezar](https://github.com/Kroshkos/Zezar):
задачи и карточки модулей подразделения с телефона.

## Возможности
- **Вход** по логину/паролю учётной записи Цезаря + адрес сервера (`POST /api/auth/token-login`),
  токен хранится в AsyncStorage, сессия восстанавливается автоматически.
- **Главная**: профиль, сводка по задачам (в работе / мои / просрочено), пространства и модули
  (`GET /api/mobile/bootstrap`).
- **Задачи**: список карточек всех модулей, поиск, фильтр по модулям, pull-to-refresh
  (`GET /api/mobile/entities`).
- **Создание задачи** (`POST /api/mobile/tasks`) и **редактирование** статуса/приоритета/срока/
  описания прямо из карточки (`PATCH /api/mobile/entities/{uid}`), включая быстрый экшен
  «Отметить выполненной». Права на редактирование приходят с сервера (`can_edit`).
- **События и push**: вкладка «События» (🔔) показывает ленту `GET /api/mobile/events` (long-poll),
  счётчик непрочитанных на иконке вкладки; Expo Push-токен устройства регистрируется на сервере
  (`POST /api/mobile/push/register`) — назначения, смены статусов и напоминания о сроках приходят
  как системные уведомления. Тап по push открывает карточку задачи. При выходе подписка деактивируется.
- **Профиль**: сведения о сервере, выходе из аккаунта с отзывом токена (`POST /api/auth/token-revoke`).

## Запуск
```bash
npm install
npx expo start        # отсканируйте QR-код через Expo Go
```
В поле «Адрес сервера» укажите публичный URL вашего Zezar (например `https://zezar.example.com`).

## Структура
```
src/
  api/        client.js (fetch + Bearer), endpoints.js (REST мобильного контура),
              offline.js (v1.4: кэш GET в AsyncStorage + очередь мутаций с ретраями)
  state/      AuthContext.js (сессия + bootstrap), NotificationsContext.js (push + long-poll лента + диспатчер очереди)
  screens/    Login, Home, Tasks, Events, NewTask, Entity, Profile
  components/ ui.js, EntityCard.js
  theme/ utils/
tests/        offline.test.js (unit-тесты оффлайн-модуля, `npm test`)
```

## Соответствие API
Мобильные эндпоинты реализованы в бэкенде: `app/mobile.py` (роутер `/api/mobile/*`) и
`app/routers/token_auth.py` (`/api/auth/token-*`). Авторизация — `Authorization: Bearer <токен>`;
поддерживается и штатными веб-API (`/api/tasks/api-list`, `/api/core/*`) благодаря гибридной
авторизации в `app/core/security.py`. Смоук-тест: `scripts/smoke_mobile_api.py`.

## v1.5 — QR-шлюз «сканировал → приложение или сайт»
Каждая карточка на сайте имеет QR-код со ссылкой `https://zezar-patfiz.waw0.amvera.tech/open/e/{uid}`:
- **Приложение установлено** → deep link `zezar://entity/{uid}?t=<одноразовый токен>` открывает карточку в приложении (гостевой вход без пароля, основная сессия сохраняется; баннер «Открыто по QR» с кнопкой возврата).
- **Приложения нет** → через ~1.4 c редирект на карточку сайта (незалогиненных — сначала на логин, затем прямо на карточку).
- Тап по push-уведомлению роутится через единый обработчик `LinkingContext`.

## Roadmap (следующие шаги)
- **v1.1**: экран деталей читает карточку точечно (`GET /api/mobile/entities/{uid}`),
  ввод срока в привычном формате ДД.ММ.ГГГГ, русские подписи приоритетов.
- **v1.3**: push через Expo + лента событий (бэкенд: MobileEvent, push_worker).
- **v1.4 (текущая сборка)**: оффлайн — кэш списков/карточек в AsyncStorage (баннер «нет сети»,
  последний снимок доступен для чтения), очередь мутаций: создание задач и правки карточек
  выполняются optimistic-locally и автоматически досылаются диспатчером после восстановления
  связи (ретраи, отбраковка логических ошибок после 5 попыток); очистка кэша при выходе из аккаунта;
  unit-тесты модуля offline (`npm test`).
- **v2.0**: тёмная тема, вложения/фото к задачам, голосовой ввод, виджет «мои задачи» на lock-screen.
